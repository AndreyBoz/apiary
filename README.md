# Мониторинг пасеки на Heltec WiFi LoRa 32 V4

В репозитории два самостоятельных проекта **ESP-IDF 5.3.x** для платы **Heltec WiFi LoRa 32 V4** (ESP32-S3, 16 МБ flash). Оба проекта используют одинаковое подключение датчиков; отличается только программная часть.

| Каталог | Назначение |
|---|---|
| [`apiary_node_LR1/apiary_node`](apiary_node_LR1/apiary_node) | ЛР1. Автономный узел: тензодатчик, микрофон, OLED, кнопка, батарея. Без Wi-Fi и MQTT. |
| [`apiary_node_LR2`](apiary_node_LR2) | ЛР2. Тот же узел + Wi-Fi, настройка через точку доступа, MQTT-телеметрия. |
| [`apiary_node_LR2/server`](apiary_node_LR2/server) | Docker-стенд: Mosquitto и веб-дашборд. |

> ⚠️ **Проверьте ревизию платы.** Распиновка ниже соответствует Heltec WiFi LoRa 32 V4. У ревизии **V4-R8** она может отличаться. Перед монтажом сверьтесь с шелкографией и [документацией Heltec](https://resource.heltec.cn/download/WiFi_LoRa_32_V4/datasheet/WiFi_LoRa_32_V4.2.0.pdf).

---

## 1. Что понадобится

- Плата Heltec WiFi LoRa 32 V4 (ESP32-S3).
- HX711 и тензодатчик (load cell) на 5–50 кг — по заданию.
- Цифровой микрофон INMP441.
- Встроенные OLED, кнопка PRG и делитель напряжения батареи — отдельно покупать не нужно.
- Аккумулятор Li-ion/LiPo 3,7 В — по желанию, для проверки заряда.
- USB-C кабель с передачей данных, провода, паяльник/макетная плата.
- Общая земля всех модулей.

Питание датчиков — **3,3 В**. Не подавайте 5 В на логику ESP32-S3 и не питайте HX711 от 5 В: его DOUT в этом случае может выдать 5 В на GPIO платы.

## 2. Распиновка

Все пины заданы в `components/config/node_config.h` (в обоих проектах файл одинаковый).

| Функция | GPIO | Примечание |
|---|---:|---|
| HX711 DOUT / DT | 47 | Вход данных |
| HX711 PD_SCK / SCK | 48 | Тактирование |
| INMP441 SCK / BCLK | 4 | I2S0 BCLK |
| INMP441 WS / LRCLK | 5 | I2S0 WS |
| INMP441 SD / DOUT | 6 | I2S0 DIN |
| OLED SDA | 17 | Встроенный OLED, I2C-адрес `0x3C` |
| OLED SCL | 18 | Встроенный OLED |
| OLED RESET | 21 | Встроенный OLED |
| VEXT | 36 | Питание внешних цепей, активный уровень — **низкий** (`VEXT_ON_LEVEL 0`) |
| ADC_CTRL | 37 | Включение делителя батареи, активный уровень — высокий |
| BAT ADC | 1 | Встроенный делитель, `ADC1_CH0`; отдельный провод не нужен |
| BUTTON / PRG | 0 | Встроенная кнопка, активный уровень — низкий, внутренняя подтяжка вверх |

## 3. Подключение датчиков

Перед монтажом **отключите USB и аккумулятор**. После сборки проверьте мультиметром отсутствие короткого замыкания между 3V3 и GND.

### 3.1. HX711 + тензодатчик

| HX711 | Куда |
|---|---|
| VCC | 3V3 |
| GND | GND |
| DOUT / DT | GPIO47 |
| PD_SCK / SCK | GPIO48 |

| Тензодатчик | HX711 |
|---|---|
| E+ | E+ |
| E− | E− |
| S+ | A+ |
| S− | A− |

- **RATE = 0 / 10 SPS.** Если на модуле есть вывод RATE, соедините его с GND. Программа рассчитана на 10 отсчётов в секунду.
- Цвета проводов тензодатчика у разных производителей отличаются — ориентируйтесь на паспорт, а не на цвет.
- Провода от тензодатчика до HX711 делайте короткими; при длинных проводах используйте экранированный кабель, экран — на GND.
- HX711 питайте от **3V3**, иначе уровень DOUT может быть 5 В.
- Если масса «прыгает», проверьте механическое крепление, питание и калибровку (раздел 8).

### 3.2. INMP441

| INMP441 | Куда |
|---|---|
| VDD | 3V3 |
| GND | GND |
| SCK / BCLK | GPIO4 |
| WS / LRCLK | GPIO5 |
| SD / DOUT | GPIO6 |
| L/R | **GND** |

- `L/R` обязательно на GND: код читает левый канал I2S. Если оставить `L/R` в воздухе или подключить к 3V3, можно получить тишину.
- Если на модуле нет подтяжки линии SD к земле, поставьте резистор **100 кОм между SD и GND**.
- Провода I2S делайте короткими, уводите их от антенны и силовых цепей.

### 3.3. OLED, кнопка и батарея

- **OLED** уже распаян на плате: SDA — GPIO17, SCL — GPIO18, RESET — GPIO21, адрес `0x3C`. Дополнительно подключать ничего не нужно. Питание внешних цепей включается уровнем `0` на GPIO36 (VEXT).
- **Кнопка PRG** уже на плате и подключена к GPIO0. Внешняя кнопка не нужна.
- **Батарея**: один элемент Li-ion/LiPo 3,7 В подключается к штатному разъёму **BAT**. Обязательно сверьте полярность контактов. Делитель напряжения и измерение уже есть на плате: измерение идёт на GPIO1 (`ADC1_CH0`), а GPIO37 включает делитель только на время замера. **Не подавайте напряжение батареи на GPIO37.**
- Процент заряда рассчитывается по таблице напряжений и является приблизительным. Без аккумулятора поля заряда на экране будут пустыми (`--`).

### 3.4. Порядок сборки

1. Отключите питание.
2. Подключите HX711 и тензодатчик, затем INMP441.
3. Проверьте общую землю и отсутствие замыканий.
4. Подключите USB-C и убедитесь, что плата определяется как COM-порт.
5. Прошейте проект и проверьте показания в мониторе ESP-IDF.

## 4. Инициализация в Visual Studio Code

### 4.1. Установить программы

1. Установите [Visual Studio Code](https://code.visualstudio.com/).
2. Установите [Git для Windows](https://git-scm.com/download/win).
3. В VS Code откройте **Extensions** (`Ctrl+Shift+X`) и установите расширение **ESP-IDF** от Espressif Systems.
4. При необходимости установите драйвер USB-UART, который используется на плате (CP210x или CH34x). Если COM-порт не появляется в диспетчере устройств — почти всегда дело в драйвере или в кабеле без передачи данных.

### 4.2. Настроить ESP-IDF

1. Нажмите `Ctrl+Shift+P` и выполните **ESP-IDF: Configure ESP-IDF Extension**.
2. Выберите **Express** (если ESP-IDF ещё не установлен) или **Use existing setup** (если уже есть).
3. Версия — **ESP-IDF 5.3.x**. Каталог установки — без пробелов и кириллицы, например `C:\Espressif`.
4. Цель — **esp32s3**.
5. Дождитесь установки Python, toolchain и ESP-IDF. Если установка уже есть, укажите путь к ней, например `C:\Espressif\frameworks\esp-idf-v5.3.6-2`.

### 4.3. Открыть проект

Открывайте **папку конкретного проекта**, а не корень репозитория: расширению нужен `CMakeLists.txt` в корне рабочей папки.

- Для ЛР1: **File → Open Folder…** → `apiary_node_LR1\apiary_node`.
- Для ЛР2: **File → Open Folder…** → `apiary_node_LR2`.

Если открыть корень `apiary`, ESP-IDF не найдёт проект. Для второго проекта откройте новое окно VS Code.

### 4.4. Выбрать цель и порт

1. `Ctrl+Shift+P` → **ESP-IDF: Set Espressif Device Target** → `esp32s3`.
2. `Ctrl+Shift+P` → **ESP-IDF: Select Port to Use** → выберите COM-порт платы (например, `COM5`).
3. Метод прошивки — **UART**.

### 4.5. Собрать, прошить, открыть монитор

Используйте команды палитры команд или иконки в нижней панели VS Code:

- **ESP-IDF: Build your Project** — сборка.
- **ESP-IDF: Flash your Project** — прошивка.
- **ESP-IDF: Monitor your Device** — монитор последовательного порта.

При первой сборке создаются `build/`, `sdkconfig` и `build/compile_commands.json`. Эти файлы не коммитятся: `sdkconfig` собирается из `sdkconfig.defaults`, а `build/` — локальный артефакт.

Выход из монитора — `Ctrl+]`.

### 4.6. Сборка из терминала

Откройте **ESP-IDF Terminal** (`Ctrl+Shift+P` → **ESP-IDF: Open ESP-IDF Terminal**) и выполните:

```powershell
cd apiary_node_LR1\apiary_node
idf.py set-target esp32s3
idf.py build
idf.py -p COM5 flash monitor
```

Для ЛР2:

```powershell
cd apiary_node_LR2
idf.py set-target esp32s3
idf.py build
idf.py -p COM5 flash monitor
```

Замените `COM5` на фактический порт. Если порт занят монитором, закройте монитор или используйте отдельный терминал.

### 4.7. Подсказки по VS Code

- Настройки расширения (путь к ESP-IDF, COM-порт, путь к `compile_commands.json`) хранятся в `.vscode/settings.json`. Этот файл **не входит в репозиторий**, потому что у каждой машины свои пути. При необходимости создайте его заново через настройки расширения.
- Для clangd после первой сборки появляется `build/compile_commands.json`. Если переходы по коду не работают, укажите в настройках clangd каталог `build` или путь к `compile_commands.json`.
- Если `idf.py` не найден в обычном терминале, используйте **ESP-IDF Terminal** или запустите `export.ps1` из каталога ESP-IDF.
- Путь к проекту не должен содержать пробелов и кириллицы. Если сборка странно ломается, перенесите папку, например, в `C:\esp\apiary`.

## 5. ЛР1: автономный узел

Проект: `apiary_node_LR1/apiary_node`.

### Что показывает OLED

- `HIVE-01 LEAF 87%` — идентификатор, роль и заряд.
- `MASS 12.34 KG` — масса по тензодатчику.
- `SOUND -42 DBFS` — уровень звука.
- `ADDR 17  4.05 V` — адрес узла и напряжение батареи.

### Кнопка

- Долгое нажатие (не менее 1 с) — открыть меню выбора роли.
- Короткое нажатие в меню — переключить указатель.
- Долгое нажатие в меню — подтвердить выбор.
- Роль хранится в оперативной памяти и после перезагрузки сбрасывается в `LEAF`.

### Что смотреть в журнале

- `role confirmed: GATEWAY` — подтверждение роли.
- `mass=... n=... raw_mean=...` — масса, число отсчётов, средний сырой код HX711.
- `audio 4x1024 rms=... dBFS` — звуковой замер. Он выполняется при запуске и затем раз в минуту.
- `battery=... mV charge=...%` — напряжение и приблизительный заряд.

### Проверка сторожевого таймера

В `components/config/node_config.h` временно установите `WATCHDOG_DEMO 1`, прошейте плату и откройте меню длинным нажатием. После проверки верните `0` и прошейте снова. Это учебный тест TWDT, в обычной работе опция должна быть выключена.

## 6. ЛР2: Wi-Fi, MQTT и дашборд

Проект: `apiary_node_LR2`.

### 6.1. Запустить сервер

Установите и запустите **Docker Desktop**. Затем в терминале:

```powershell
cd apiary_node_LR2\server
docker compose up -d --build
```

При первой сборке нужен интернет: скачиваются образы Mosquitto/nginx и пакет `mqtt` для дашборда.

После запуска:

- дашборд — <http://localhost:8080>;
- MQTT TCP — `localhost:1883` (доступен в локальной сети);
- MQTT WebSocket — `localhost:9001` (только на этом компьютере).

Остановить стенд:

```powershell
docker compose down
```

Остановить и удалить данные брокера:

```powershell
docker compose down -v
```

### 6.2. Первая настройка платы

1. Прошейте ЛР2.
2. На OLED и в мониторе появятся SSID вида `apiary-XXXXXX` и пароль `HIVEXXXXXX`.
3. Подключитесь к этой точке доступа с телефона или ноутбука.
4. Откройте <http://192.168.4.1/>.
5. Укажите:
   - SSID сети **2,4 ГГц**;
   - пароль Wi-Fi;
   - IP-адрес ноутбука с Mosquitto в локальной сети (например, `192.168.1.50`);
   - порт `1883`.
6. Нажмите **Сохранить и перезапустить**. Плата перезагрузится и подключится к Wi-Fi и MQTT.

IP-адрес ноутбука в Windows можно узнать командой:

```powershell
ipconfig
```

Ноутбук и плата должны быть в одной сети без изоляции клиентов. В Windows разрешите входящие TCP-соединения на порт **1883** для используемой частной сети.

### 6.3. Если настройки введены неверно

Плата хранит их в NVS. Сбросить настройки можно полной очисткой flash:

```powershell
idf.py -p COM5 erase-flash
idf.py -p COM5 flash monitor
```

`erase-flash` стирает и прошивку, и сохранённые настройки, поэтому после неё нужно прошить проект заново.

### 6.4. Несколько стендов

Для каждого стенда задайте уникальные значения:

- `HIVE_ID` и `NODE_ADDRESS` — в `components/config/node_config.h`;
- `GATEWAY_ID` — в `main/network.c`;
- при необходимости `APIARY_ID` — в `main/network.c`.

После изменения констант пересоберите и прошейте плату.

### 6.5. MQTT-топики

| Топик | QoS | Retain | Содержимое |
|---|---:|---|---|
| `apiary/ap01/hive/HIVE-01/telemetry` | 0 | да | JSON измерений раз в 30 с |
| `apiary/ap01/gateway/gw01/status` | 0 | да | `online` с `ts` при подключении, `offline` через LWT |

Пример телеметрии:

```json
{
  "node_addr": 23,
  "ts": 1730000000000,
  "weight_g": 12345,
  "rms": 0.0123,
  "band_100_200_ratio": 0,
  "swarm_flag": false,
  "battery_pct": 87
}
```

Поля:

- `node_addr` — адрес узла (`NODE_ADDRESS`);
- `ts` — Unix-время в миллисекундах UTC; `0`, пока не выполнен SNTP;
- `weight_g` — масса в граммах или `null`;
- `rms` — уровень звука `0…1` или `-1`, если замера нет;
- `band_100_200_ratio` — доля энергии 100–200 Гц (в ЛР2 всегда `0`, появится в следующих работах);
- `swarm_flag` — признак роения (в ЛР2 всегда `false`);
- `battery_pct` — заряд в процентах или `null`.

### 6.6. Проверка MQTT

В каталоге `apiary_node_LR2/server` откройте отдельный терминал:

```powershell
docker compose exec mosquitto mosquitto_sub -t "apiary/#" -v
```

Тестовая публикация:

```powershell
docker compose exec mosquitto mosquitto_pub -t apiary/test/hive/x/telemetry -m '{"weight_g":1000}'
```

Удаление retained-сообщения одного улья:

```powershell
docker compose exec mosquitto mosquitto_pub -r -n -t "apiary/ap01/hive/HIVE-01/telemetry"
```

После удаления обновите страницу дашборда: строка исчезнет и появится снова после следующей публикации.

### 6.7. Дашборд

- Данные приходят по WebSocket на `ws://localhost:9001/mqtt`.
- Последнее измерение восстанавливается из retained-сообщения.
- График массы хранится в памяти вкладки за последние 10 минут.
- Если данные старше 3 минут, строка становится серой.
- Дашборд открывается только на том компьютере, где запущен Docker (`localhost`). Порты 8080 и 9001 привязаны к `127.0.0.1`.

## 7. Калибровка тензодатчика

Константы находятся в `components/config/node_config.h`:

```c
#define SCALE_TARE 84215.0
#define SCALE_COUNTS_PER_GRAM 21.425
```

Порядок:

1. Запишите средний сырой код `raw1` без груза и `raw2` с известной массой `m2` в граммах.
2. Рассчитайте:

```text
SCALE_COUNTS_PER_GRAM = (raw2 - raw1) / m2
SCALE_TARE = raw1
```

Если используете две известные массы `m1` и `m2`:

```text
SCALE_COUNTS_PER_GRAM = (raw2 - raw1) / (m2 - m1)
SCALE_TARE = raw1 - SCALE_COUNTS_PER_GRAM * m1
```

3. Обновите обе константы, пересоберите и прошейте проект.
4. Проверьте третьим грузом. При необходимости повторите калибровку.

Средний сырой код удобно смотреть в журнале ЛР1/ЛР2 в строке `raw_mean=...`.

## 8. Диагностика

| Проблема | Что проверить |
|---|---|
| Нет COM-порта | Кабель с передачей данных, драйвер CP210x/CH34x, диспетчер устройств. Попробуйте другой USB-порт. |
| Плата не прошивается | Закройте монитор, который занимает порт. Попробуйте вручную: удерживайте **BOOT**, нажмите **RESET**, отпустите **BOOT**, затем прошейте. |
| `idf.py` не найден | Используйте **ESP-IDF Terminal** или `export.ps1` из каталога ESP-IDF. |
| Сборка ломается на путях | Уберите пробелы и кириллицу из пути к проекту. |
| OLED пустой | Проверьте VEXT (GPIO36, активный низкий), ревизию платы, адрес `0x3C`, линию RESET. |
| HX711 не даёт данные | DOUT/SCK не перепутаны, питание 3,3 В, общая земля, RATE=0, правильная схема тензодатчика. Если DOUT постоянно высокий — новых отсчётов нет. |
| Масса нестабильна | Калибровка, механическое крепление, вибрация, длина проводов, стабильное питание. |
| INMP441 молчит | `L/R` на GND, подтяжка SD 100 кОм, правильные BCLK/WS/SD, питание 3,3 В. |
| Wi-Fi не подключается | Только 2,4 ГГц, WPA2, плата и ноутбук в одной сети, нет изоляции клиентов. |
| MQTT не подключается | IP брокера, порт 1883, брандмауэр Windows, `allow_anonymous true`, контейнер Mosquitto запущен. |
| Дашборд пустой | Откройте `http://localhost:8080`, проверьте консоль браузера, что `mqtt.min.js` загрузился и WebSocket 9001 доступен. |
| Данные «устарели» | Проверьте `ts` и SNTP: без синхронизации времени `ts` равен `0`. |

## 9. Публикация репозитория в GitHub

Создайте на GitHub **пустой** репозиторий (без README, `.gitignore` и лицензии), затем привяжите его:

```powershell
git remote add origin https://github.com/<USER>/<REPO>.git
git branch -M main
git push -u origin main
```

Если Git попросит пароль, используйте не пароль от аккаунта, а **Personal Access Token** с правом `repo` (GitHub → Settings → Developer settings → Personal access tokens), либо войдите через Git Credential Manager.

В репозиторий не попадают:

- `build/`, `build_old/` — результаты сборки;
- `sdkconfig`, `sdkconfig.old` — генерируются из `sdkconfig.defaults`;
- `.vscode/settings.json` — локальные пути и COM-порт;
- сохранённые Wi-Fi-настройки — они хранятся в NVS платы, а не в исходниках.
