# ЛР2 Wi-Fi и MQTT

Проект ESP-IDF 5.3.x для Heltec WiFi LoRa 32 V4. Использует GPIO и датчики ЛР1. Один стенд передаёт телеметрию своего улья и состояние шлюза. Для второго стенда задайте уникальные HIVE_ID и NODE_ADDRESS в components/config/node_config.h и GATEWAY_ID в main/network.c перед сборкой. Радиосвязь между стендами появится в ЛР4.

## Запуск

1. Распакуйте ZIP в каталог без пробелов и кириллицы, например C:\Users\bozhov\esp\apiary_node_LR2.
2. Откройте server в терминале с запущенным Docker Desktop и выполните docker compose up -d --build. При первой сборке нужны Docker Hub и npm. Откройте http://localhost:8080 на ноутбуке.
3. Откройте корень проекта в VS Code. Выберите ESP-IDF 5.3.x, цель esp32s3 через ESP-IDF: Set Espressif Device Target и COM-порт платы. Выполните Build и Flash. На OLED и в журнале появятся SSID apiary-XXXXXX и пароль.
4. Подключитесь к AP с телефона, откройте http://192.168.4.1/ и введите SSID сети 2,4 ГГц, пароль и LAN IPv4 ноутбука с Mosquitto. Используйте порт 1883. Ноутбук и плата должны быть в одной сети без изоляции клиентов. Проверьте IP командой ipconfig. Для доступа с платы Windows должна разрешать TCP 1883 в используемой частной сети.
5. После сохранения плата перезапустится, подключится к Wi-Fi и MQTT. Следите за ESP-IDF Monitor. Для смены настроек после ошибочного ввода используйте idf.py erase-flash и затем снова прошейте ЛР2. Erase Flash стирает всё содержимое flash, в том числе текущую прошивку и сохранённые настройки.

MQTT TCP доступен в локальной сети по 1883, браузерные порты 9001 и 8080 доступны на ноутбуке. Анонимный TCP используйте в изолированной учебной сети. Для проверки обрыва ноутбук и браузер должны сохранять связь с брокером. Например, отключите точку доступа, используемую только платой, или выключите питание платы для проверки LWT отдельно.

## Сообщения

| Топик | QoS | Retain | Содержимое |
|---|---:|---|---|
| apiary/ap01/hive/HIVE-01/telemetry | 0 | да | JSON измерений раз в 30 с |
| apiary/ap01/gateway/gw01/status | 0 | да | online с ts при подключении, offline через LWT |

Телеметрия содержит node_addr (адрес узла), ts (Unix-мс UTC, 0 до SNTP), weight_g (граммы), rms (0…1 или −1), band_100_200_ratio и swarm_flag (0 и false до ЛР5), battery_pct (процент). При отсутствии измерения массы или заряда соответствующее поле содержит null, экран показывает пропуск. Процент заряда наследуется из ЛР1 и проверяется с подключённой батареей.

## Проверки для отчёта

В каталоге server запустите подписку в отдельном терминале:

```powershell
docker compose exec mosquitto mosquitto_sub -t "apiary/#" -v
```

Тестовый топик можно проверить из второго терминала:

```powershell
docker compose exec mosquitto mosquitto_pub -t apiary/test/hive/x/telemetry -m '{"weight_g":1000}'
```

1. Откройте дашборд после публикации и нажмите F5. Последнее измерение восстанавливается из retained. График хранится в памяти вкладки и строится заново.
2. Отключите сеть платы, оставив брокер доступным, дождитесь offline. Включите сеть и проверьте online без перезагрузки платы. При отсутствии свежего ts больше 3 мин строка становится серой.
3. Выполните docker compose restart mosquitto и проверьте повторное подключение. Удалите retained одного улья командой ниже, обновите страницу и дождитесь восстановления строки следующей публикацией.
4. Для скриншота с двумя ульями используйте два стенда или добавьте вторую строку тестовой публикацией. Отметьте в отчёте, если вторая строка тестовая.

```powershell
docker compose exec mosquitto mosquitto_pub -r -n -t "apiary/ap01/hive/HIVE-01/telemetry"
```
